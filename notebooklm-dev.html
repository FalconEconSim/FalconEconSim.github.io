Developer Notes & Feasibility
ChosenWhy Claude chat instead of a NotebookLM “bridge” link?

The professor wanted a NotebookLM link that always reflects the latest site content. The blocker (below) is that NotebookLM has no real API and can’t stay auto-synced — sources are refreshed by hand. So Idea 2 is now a Claude chat embedded directly in the page: a small Cloudflare Worker holds the Anthropic API key as a server-side secret and injects the course content as context, so students just ask — no key, no separate app. Updating its knowledge is a content rebuild + redeploy, fully under our control. Scoped to Week 2 for this prototype.

PartialCan we auto-sync GitHub content into NotebookLM?

Not cleanly, and not officially. There is no public NotebookLM API. The community CLI tmc/nlm can create/list notebooks, add sources (URLs, PDFs, text), generate audio/video overviews, and run with --json for scripting — so a GitHub Action could re-push sources whenever the site changes. The catch: it authenticates by extracting browser cookies/auth tokens (Chrome/Brave/Edge) rather than a real API key. Those tokens expire, so an unattended CI job would break periodically and need a human to refresh credentials. Treat automation as “possible but fragile,” not “set and forget.”

YesCan a notebook be shared publicly so students just click a link?

Yes — NotebookLM added public notebooks (Share → “Anyone with a link”). Viewers can read the sources, ask questions in chat, and generate Audio Overviews / Mind Maps / FAQs, but cannot edit the source set. That is exactly the “ask the course” experience. Main limits: it’s one shared notebook for everyone (no per-student state), and updates to sources are made by the owner, not the viewer.

PartialCan the Kaltura lecture videos become NotebookLM sources?

Indirectly. NotebookLM accepts YouTube links (and uses their transcripts) but not Kaltura URLs directly. Options: mirror the lectures to (unlisted) YouTube and add those, or export each lecture’s transcript/captions and add them as text sources. Either works; both are manual steps per video.

YesCan a Video Overview be embedded in our own page?

Not as a live iframe from notebooklm.google.com, but the generated video can be downloaded and the notebook/artifact can be shared via link. So the embeddable route is: generate → download the MP4 → self-host (or push to Kaltura/YouTube) → embed with a normal player. That’s the mock-up in Section 1. Note cinematic Video Overviews currently require a Google AI Ultra subscriber to generate and are English-only at launch (overviews in 80+ languages otherwise).

Recommendation

Recap video: Worth piloting — but treat NotebookLM as a production tool, not an integration. Generate the recap, download it, and host it the same way as the existing lecture videos so it loads reliably and looks on-brand. Pilot one week (the Week 2→3 recap you already made) before committing to all eight.

“Ask the course”: Went with the embedded Claude chat over a NotebookLM bridge — it’s live in-page, needs no student logins or keys (the Worker hides the API key), and its knowledge is fully under our control. Next steps if it pilots well: extend the corpus to all eight weeks, and before opening it to the whole class add rate limiting / Cloudflare Turnstile and per-week scoping. A public NotebookLM notebook (below) remains a fine zero-code fallback.
