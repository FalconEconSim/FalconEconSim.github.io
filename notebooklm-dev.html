Weekly Recap Video & NotebookLM Bridge

Two working pieces: (1) a real ≤5-min NotebookLM-generated recap video for the top of each week, watched before the next class, and (2) a live “Ask the Course AI” chat — a free, open-source model that runs in the browser (no key, no cost) — the practical answer to the professor’s “notebook that always knows the latest site” idea. Idea 2 · Ask the course

Ask the Course AI

The professor wanted a link to a NotebookLM that always reflects the latest site content — but NotebookLM can’t stay auto-synced. So instead, this is a free, open-source AI that runs entirely in your browser — no sign-up, no API key, no cost, ever. It’s loaded with the Week 2 essentials and a map of the site, so you can ask questions or have it draft study notes to download. The first time you use it, a small model downloads to your browser once, then runs locally on your own machine.

Hi! I’m a small open-source AI running right in your browser — free, private, no sign-up. I’ve got the Week 2 essentials loaded (preferences, indifference curves, the budget constraint, the optimum). Ask me a question or tap a starter. Heads-up: I’m a lightweight model, so sanity-check anything important.
How it works: the model runs 100% in your browser via WebGPU — nothing is sent to a server, there’s no API key, and it costs nothing to run. The Week 2 course content is baked into the page as the model’s context. Needs a recent Chrome or Edge and a reasonably capable computer; the first message triggers a one-time model download. Scoped to Week 2 for this prototype; the same setup extends to every week.
Developer Notes & Feasibility
ChosenWhy an in-browser open-source AI instead of a NotebookLM “bridge”?

The professor wanted a NotebookLM link that always reflects the latest site content. The blocker (below) is that NotebookLM has no real API and can’t stay auto-synced. The constraint we then chose: zero cost, no API keys, nothing to maintain. The fit is an open-source model run client-side via WebLLM / WebGPU (e.g. Llama 3.2, Qwen2.5): it’s free forever, needs no server or key, hosts on plain GitHub Pages, and keeps every conversation private on the student’s machine. Trade-offs we accepted: the model is much smaller than a hosted frontier model (weaker answers), there’s a one-time ~1 GB download, and it needs a WebGPU browser + decent hardware. Course content is baked into the page; updating it is a content edit + push. Scoped to Week 2 for this prototype. (A paid/keyed option like a Cloudflare Worker + the Anthropic API gives far better answers if budget ever allows.)

PartialCan we auto-sync GitHub content into NotebookLM?

Not cleanly, and not officially. There is no public NotebookLM API. The community CLI tmc/nlm can create/list notebooks, add sources (URLs, PDFs, text), generate audio/video overviews, and run with --json for scripting — so a GitHub Action could re-push sources whenever the site changes. The catch: it authenticates by extracting browser cookies/auth tokens (Chrome/Brave/Edge) rather than a real API key. Those tokens expire, so an unattended CI job would break periodically and need a human to refresh credentials. Treat automation as “possible but fragile,” not “set and forget.”

YesCan a notebook be shared publicly so students just click a link?

Yes — NotebookLM added public notebooks (Share → “Anyone with a link”). Viewers can read the sources, ask questions in chat, and generate Audio Overviews / Mind Maps / FAQs, but cannot edit the source set. That is exactly the “ask the course” experience. Main limits: it’s one shared notebook for everyone (no per-student state), and updates to sources are made by the owner, not the viewer.

PartialCan the Kaltura lecture videos become NotebookLM sources?

Indirectly. NotebookLM accepts YouTube links (and uses their transcripts) but not Kaltura URLs directly. Options: mirror the lectures to (unlisted) YouTube and add those, or export each lecture’s transcript/captions and add them as text sources. Either works; both are manual steps per video.

YesCan a Video Overview be embedded in our own page?

Not as a live iframe from notebooklm.google.com, but the generated video can be downloaded and the notebook/artifact can be shared via link. So the embeddable route is: generate → download the MP4 → self-host (or push to Kaltura/YouTube) → embed with a normal player. That’s the mock-up in Section 1. Note cinematic Video Overviews currently require a Google AI Ultra subscriber to generate and are English-only at launch (overviews in 80+ languages otherwise).

Recommendation

Recap video: Worth piloting — but treat NotebookLM as a production tool, not an integration. Generate the recap, download it, and host it the same way as the existing lecture videos so it loads reliably and looks on-brand. Pilot one week (the Week 2→3 recap you already made) before committing to all eight.

“Ask the course”: Went with a free, open-source AI running in the browser (WebLLM) over a NotebookLM bridge — it’s live in-page, costs nothing, needs no keys or student logins, and keeps chats private on-device. Next steps if it pilots well: extend the baked-in content to all eight weeks, try a slightly larger model for better answers, and add a clear “first-load downloads ~1 GB” heads-up. If answer quality proves too limiting for students, the keyed Cloudflare Worker + Anthropic path (kept on hand) is the upgrade. A public NotebookLM notebook (below) remains a fine zero-code fallback.
