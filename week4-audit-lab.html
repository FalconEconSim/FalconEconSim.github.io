Week 4 Audit Lab

Ten copies of the Week 4 interactive page, each carrying a different overlap-detection system that runs live in a panel (bottom-right) and draws red boxes over what it finds. Built to answer one question: which audit approach actually catches text overlaps in canvas + SVG figures? Open any version, then drag points, sweep sliders, and resize the window to watch its detector react.

Why this exists. Two overlaps shipped that earlier audits missed: a canvas label sitting on a dot (nothing was in the DOM to inspect), and a video label whose bounding box cleared the next label by 0.13–0.28 units yet still read as overlapping. Lesson baked into these systems: you must (1) see canvas-drawn text, (2) check across interaction + viewport states, and (3) flag near-touch crowding, not only strict box intersection.

What each system caught (same page, same run)

Cross-referencing the ten on identical content shows the trade-offs: the DOM-only and SVG-only systems are blind to Week 4’s canvas text; the temporal and aspect-ratio systems find the most because overlaps here are state- and size-dependent; the pixel/OCR systems act as render-truth cross-checks; the vision system is the perceptual judge.

The verdict

No single system is enough. A practical pipeline runs Canvas instrumentation (2) for the cheap static truth, layers Temporal (4) + Aspect-ratio (6) + Combinatorial (7) to cover interaction & responsive states, uses Pixel (3) / Projection-OCR (9) as render-truth cross-checks, and finishes with the Vision (5) pass for perceptual crowding that geometry can only approximate. All of them now flag near-touch crowding, the class that slipped through before.
